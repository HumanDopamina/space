Lección 1 · Sistema de inventario

El mapa del proyecto Django

Tu primera victoria: distinguir el proyecto Django de una aplicación y levantar la base del inventario.

La idea esencial

Piensa en el proyecto como el edificio completo y en cada aplicación como un departamento especializado dentro de él. El proyecto contiene la configuración común: qué base de datos usar, qué aplicaciones están activas, qué URLs existen y cómo se ejecuta el sitio.

Una aplicación agrupa una capacidad concreta y reutilizable: sus modelos, vistas, URLs, administración y pruebas. En nuestro caso, el edificio es el sistema de inventario. catalogo guardará productos, categorías y proveedores; movimientos registrará entradas y salidas; usuarios se ocupará de cuentas y permisos.

La separación evita mezclar todo en un solo archivo. Por eso el modelo Producto irá en catalogo/models.py, mientras que config/settings.py le dice al proyecto que la aplicación catalogo existe y debe cargarse.

Regla práctica: el proyecto coordina el sitio entero; una aplicación implementa una capacidad del negocio. Un proyecto puede tener varias aplicaciones, y cada aplicación debe tener un propósito reconocible.

Hazlo ahora

En PowerShell, dentro de una carpeta de trabajo:

py -m venv .venv
.\.venv\Scripts\Activate.ps1
py -m pip install django djangorestframework
django-admin startproject config .
py manage.py startapp catalogo
py manage.py migrate
py manage.py runserver

Abre http://127.0.0.1:8000/; verás la página de bienvenida de Django. Después revisa el árbol: manage.py es el punto de entrada para comandos administrativos como runserver, config/settings.py configura el proyecto y catalogo/ será el hogar de los modelos de productos. El comando runserver no crea manage.py: ese archivo lo crea startproject.

Recuperación

Sin mirar la lección, responde: ¿dónde pondrías el modelo Producto y dónde registrarías que catalogo está instalado? Luego comprueba tu respuesta en catalogo/models.py y config/settings.py.

Tu siguiente paso

Cuando tengas el servidor funcionando, dime qué aparece en la página y qué archivos creó el comando. Con eso diseñaremos el primer modelo de producto.
